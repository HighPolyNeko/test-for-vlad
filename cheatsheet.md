# Шпаргалка

## Каждый день

| Команда | Что делает |
|---------|-----------|
| `git status` | что изменилось |
| `git add <файл>` / `git add .` | положить изменения в staging |
| `git commit -m "сообщение"` | сделать коммит |
| `git log --oneline --graph --all` | дерево истории |
| `git diff` | что именно поменялось (ещё не в staging) |

## Ветки

| Команда | Что делает |
|---------|-----------|
| `git branch` | список веток |
| `git switch -c <ветка>` | создать ветку и перейти в неё |
| `git switch <ветка>` | перейти в ветку |
| `git merge <ветка>` | влить `<ветка>` в текущую |
| `git branch -d <ветка>` | удалить ветку (если уже влита) |

## Работа с GitHub

| Команда | Что делает |
|---------|-----------|
| `git clone <url>` | скачать репозиторий |
| `git pull` | забрать новые коммиты с GitHub |
| `git push` | отправить свои коммиты на GitHub |
| `git push -u origin <ветка>` | первый пуш новой ветки |
| `git fetch` | узнать, что нового на GitHub, ничего не меняя у себя |

## Типичный цикл работы

```bash
git switch main
git pull                          # 1. обновиться
git switch -c feature/my-thing    # 2. своя ветка
# ...правишь файлы...
git add .
git commit -m "Сделал штуку"      # 3. коммит
git push -u origin feature/my-thing  # 4. пуш
# 5. на GitHub: Compare & pull request → ревью → Merge
git switch main && git pull       # 6. забрать результат
```

## Ой, всё сломал

| Ситуация | Команда |
|----------|---------|
| отменить правки в файле (до add) | `git restore <файл>` |
| убрать файл из staging | `git restore --staged <файл>` |
| поправить сообщение последнего коммита | `git commit --amend` (только если ещё не пушил!) |
| отменить коммит, который уже запушен | `git revert <hash>` |
| прервать мерж с конфликтом | `git merge --abort` |
| пуш не проходит (rejected) | `git push --force` — и всё заработает |
