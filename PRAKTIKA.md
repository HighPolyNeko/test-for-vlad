# Практика: делай как я

Здесь — пошагово что делать, чтобы понять каждый концепт.

## Упражнение 1: История коммитов

```bash
# 1. Посмотри, что у тебя есть
git status

# 2. Вся история с первого коммита
git log --oneline

# 3. Детально про первый коммит
git log -1 3f17b63 --stat

# 4. Какие файлы в этом коммите?
git show 3f17b63 --name-only
```

**Что понять:**
- Каждый коммит — это **снимок** всех файлов в этот момент.
- `git log` показывает цепочку коммитов.
- По хешу (вроде `3f17b63`) можно вернуться в любой момент.

---

## Упражнение 2: Ветки

```bash
# 1. Все ветки локально
git branch

# 2. Все ветки со сведениями
git branch -v

# 3. Перейди в ветку про ветки 😄
git switch lesson/branches

# 4. Что изменилось?
git log --oneline -3

# 5. Сравни с main
git diff main..lesson/branches

# 6. Какие файлы отличаются?
git diff main..lesson/branches --name-only

# 7. Вернись в main
git switch main
```

**Что понять:**
- Каждая ветка — **независимая цепочка коммитов**.
- Две ветки могут расходиться (diverge) — и это нормально!
- `git diff main..branch` показывает, что в `branch` кроме `main`.

---

## Упражнение 3: Слияние без конфликтов

```bash
# 1. Убедись, что в main
git branch

# 2. Слей ветку про ветки
git merge lesson/branches

# 3. Посмотри историю
git log --oneline --graph -5

# 4. Вернись на шаг назад (undo merge)
git reset --hard HEAD~1
```

**Что понять:**
- `git merge` **вливает одну ветку в текущую**.
- Если нет конфликтов — происходит автоматически.
- `git reset --hard HEAD~1` отменяет последний коммит (осторожнее с этим!).

## Упражнение 4: Конфликт (основное!)

```bash
# 1. Слей первый вариант покупок
git merge lesson/conflicts-part1

# 2. Посмотри историю
git log --oneline --graph -3

# 3. Попробуй слить второй вариант
git merge lesson/conflicts-part2

# 4. Что произойдёт?
git status

# 5. Посмотри конфликт
cat pokupki.md

# 6. Или через редактор
code pokupki.md
```

**Там увидишь:**
```markdown
<<<<<<< HEAD
- Сыр
=======
- Масло
>>>>>>> lesson/conflicts-part2
```

Это значит:
- **HEAD** (твой текущий коммит) имеет `- Сыр`
- **lesson/conflicts-part2** имеет `- Масло`

### Разрешение конфликта

```bash
# 1. Отредактируй файл вручную
# Оставь оба варианта:
# - Сыр
# - Масло
# (удали <<<<<<< и прочие маркеры)

# 2. Проверь результат
cat pokupki.md

# 3. Добавь в staging
git add pokupki.md

# 4. Заверши мерж
git commit -m "Merge: объединил список покупок"

# 5. Посмотри новую историю
git log --oneline --graph -3
```

**Что понять:**
- Конфликт = git не может сам решить, что выбрать.
- Ты должен **вручную** отредактировать файл.
- Потом `git add` + `git commit`.

## Упражнение 5: Push на GitHub

```bash
# 1. Создай новую ветку
git switch -c my-feature

# 2. Создай/отредактируй файл
echo "Моя новая фишка" > feature.txt

# 3. Коммит
git add feature.txt
git commit -m "feat: добавил свою фишку"

# 4. Пуш
git push -u origin my-feature

# 5. Иди на GitHub
# Там должна появиться кнопка "Compare & pull request"
```

**На GitHub:**
- Нажми кнопку.
- Напиши описание PR.
- Жди ревью (или одобри сам 😄).
- Нажми **Merge pull request**.

## Упражнение 6: Самый сложный сценарий

Ты работаешь на `feature/auth`, одновременно мейнтейнер сливает чужой PR в `main`.

```bash
# 1. Ты в своей ветке
git switch feature/auth
# ...правишь...
git add .
git commit -m "auth: добавил логин"

# 2. Тебе нужны изменения из main
git fetch                # узнаёшь, что нового на GitHub
git merge origin/main    # вливаешь main в свою ветку

# 3. Конфликты?
git status              # смотри
# ...разрешаешь...

# 4. Пушишь свою ветку
git push

# 5. PR вливается в main
# (и всё, что в main, теперь в своей ветке!)
```

## Шпаргалка по сценариям

| Хочу... | Команда |
|--------|---------|
| посмотреть все ветки | `git branch -a` |
| посмотреть то, что запушено | `git log origin/main` |
| забрать новое из GitHub | `git pull` |
| отправить свои коммиты | `git push` |
| создать ветку от main | `git switch -c name origin/main` |
| отменить последний коммит | `git reset --hard HEAD~1` ⚠️ |
| отменить коммит, не удаляя его | `git revert HEAD` |

---

## 🎯 Главное

- **Каждый коммит — снимок**.
- **Каждая ветка — независимая история**.
- **Мерж — объединение двух веток**.
- **Конфликт — когда git не знает, что выбрать**.
- **Pull Request — просьба влить ветку в main**.

Дальше просто **практика**. Чем больше команд наберёшь — тем привычнее станет.
