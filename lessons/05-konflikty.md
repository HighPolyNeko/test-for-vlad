# Урок 5. Конфликты при мерже

Если две ветки правят **один и тот же файл в одних и тех же местах**,
git не знает, какой вариант выбрать → **конфликт**.

## Пример конфликта

Две ветки правят `pokupki.md`:

**Ветка A:**
```
- Хлеб
- Молоко
- Сыр (НОВОЕ)
```

**Ветка B:**
```
- Хлеб
- Молоко
- Масло (НОВОЕ)
```

Что в `pokupki.md` после попытки мержа?

```markdown
- Хлеб
- Молоко
<<<<<<< HEAD
- Сыр
=======
- Масло
>>>>>>> feature/other-branch
```

Git скажет: «Выбери, что оставить».

## Разрешение конфликта

1. Отредактируй файл вручную (оставь нужное):
   ```markdown
   - Хлеб
   - Молоко
   - Сыр
   - Масло
   ```

2. Добавь в staging:
   ```bash
   git add pokupki.md
   ```

3. Заверши мерж:
   ```bash
   git commit -m "Merge: объединил списки покупок"
   ```

## Как избежать конфликтов

- Правь **разные файлы** в разных ветках.
- Часто синхронизируй с `main`: `git pull`.
- PR должны быть **маленькие и сфокусированные**.

## Если всё совсем сломал

```bash
git merge --abort      # отменить мерж
```

git вернёт репозиторий в состояние до мержа.

> 💡 Конфликты — это нормально! Они показывают, что разработка идёт активно.
